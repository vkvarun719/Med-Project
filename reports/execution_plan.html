Phase 1: Backend Clean Architecture & Neon Database

Phase 1 Objectives & Deliverables
Refactor senior's backend code out of automation/ into /clinic-system/backend. Secure all credentials via .env, implement Pydantic v2 validation, and support height & BMI calculations.
  • Database Migration: Create target tables in Neon PostgreSQL:
    • patients (id, name, age, gender, phone, barcode UNIQUE, created_at)

  • BMI Formula Implementation:

    height_m = height_cm / 100.0; bmi = round(weight_kg / (height_m ** 2), 2)

  • Validation Rules: Weight: 1.0 kg to 350.0 kg; Height: 30.0 cm to 250.0 cm; Phone: 10 digits regex.

  • Collision-Safe Barcodes: Update barcode_generator.py to query the DB in a loop to ensure 100% collision-free 8-char codes.

Phase 2: Raspberry Pi Autonomous Clinic Station

Phase 2 Objectives & Deliverables (Heart of Project)
Build a production-grade, modular Python daemon running natively on the Raspberry Pi with hardware drivers, stability algorithms, and offline resilience.
Finite State Machine (session.py):
  1. IDLE: Waiting for patient barcode scan.
  2. SCANNED: Active patient locked; tare scale if empty.
  3. MEASURING: Continuous streaming of Weight & Height.
  4. STABLE: N consecutive values within tolerance delta.
  5. SENT: Transmitted to backend (or buffered in SQLite).
  6. RESET: Audio feedback (beep) & return to IDLE.
Resilient Offline Buffering (api_client.py):

When Wi-Fi drops, the Pi does not crash or drop data. Unsent readings are persisted in a local SQLite file (buffer.db). A background worker thread checks Wi-Fi connectivity and flushes the queue via exponential backoff.

Stability Check Algorithm Specification (stability.py)

The stability filter maintains two rolling FIFO queues of size N (default N = 5 samples, at 5 Hz = 1.0 second window). A reading is declared stable if and only if:

max(weight_buffer) - min(weight_buffer) <= weight_tolerance (e.g. 0.2 kg) AND max(height_buffer) - min(height_buffer) <= height_tolerance (e.g. 0.5 cm) AND average(weight_buffer) >= min_patient_weight (e.g. 5.0 kg)

Phase 3: React Frontend Redesign & Print System

Phase 3 Objectives & Deliverables
Elevate the user experience from an unstyled prototype to a clean, clinic-ready dashboard with live measurement streaming and printable patient cards.
  • Printable Patient Card: Barcode sticker printable directly on standard thermal label printers (or standard A4) with patient name, age, phone, barcode graphic, and generation date.
  • Real-time Station Status Card: Visual gauge displaying live station state (IDLE, MEASURING..., STABLE) without locking the UI.
  • Multi-Metric Analytics Dashboard:
    • Weight, Height, and BMI trend line charts using Chart.js.
    • Color-coded clinical BMI badges: Underweight (< 18.5) Normal (18.5 - 24.9) Overweight (25.0 - 29.9) Obese (≥ 30.0)
